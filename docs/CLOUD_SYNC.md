# 계정 및 클라우드 동기화

## 이번 단계에서 제공하는 것

로그인과 외부 데이터베이스 없이, 브라우저 localStorage(`nutrivibe:*`)를 다른 기기로 옮길 수 있습니다. 내 프로필 하단의 "데이터 백업 및 기기 간 이동"에서 사용합니다.

포함하는 데이터:

- 프로필(단백질 목표 포함)
- 입력 조건, 최근 생성 결과, 즐겨찾기, 생성 기록
- 쇼핑리스트
- 포인트·레벨·업적·식재료 도감
- 주간 식단표
- 식재료 구매일·유통기한
- 오늘 영양 기록

가져오기 방식:

- **병합**: 목록성 데이터는 합치고, 프로필과 최근 생성 결과는 더 최근 값을 유지합니다. 같은 주의 식단은 고정한 끼니를 우선합니다.
- **교체**: 이 기기의 `nutrivibe:*` 항목을 지우고 가져온 데이터로 바꿉니다.

비로그인 사용은 계속 이 기기의 localStorage만 사용합니다. 동기화 코드와 JSON 파일은 서버에 저장하지 않습니다.

## 전체 클라우드 계정은 이후 단계

Supabase, Firebase, Clerk처럼 계정과 클라우드 DB를 붙이려면 프로젝트 소유자가 서비스를 만들고 키를 발급해야 합니다. 그 환경이 준비되기 전에는 인증 화면이나 외부 DB 의존성을 넣지 않습니다.

소유자가 Supabase를 선택한 뒤 이어서 할 수 있는 작업:

1. Supabase에서 프로젝트를 만들고 Email 또는 GitHub 로그인을 켭니다.
2. `user_data (user_id, data jsonb, updated_at)` 테이블과 본인 행만 접근하는 RLS를 만듭니다.
3. `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`를 배포 환경 변수로 등록합니다. service role 키는 넣지 않습니다.
4. 로그인 시 `lib/backup.ts`의 `data`를 그대로 업서트하고, 충돌은 `updated_at`이 최신인 쪽을 따릅니다. 로그인하지 않은 사용자는 지금처럼 localStorage만 사용합니다.
